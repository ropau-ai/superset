**Date:** 2026-07-09 · **Branch:** `audit/qa-e2e` (off `integration/cockpit`) · **App:** `apps/mobile`
**Method:** exhaustive code-trace of every routed screen (`app/**`) + its screen implementation (`screens/**`), hooks, and the relay/collections data layer. Each flow is traced to its *real* behavior with `file:line` evidence. Live-device automation was **not** run (see [§Maestro](#maestro-e2e-harness) for why + the authored harness).

## TL;DR

- **62 flows** traced. **PASS: 44** · **BUG: 15** · **DEFERRED-empirical (needs live host/backend): 3**.
- **2× P0** — both on the hero flow (tap the Emilien card):
  - **P0-1** the Emilien chat screen has **no visible back button** when opened from the cockpit (deep-link into a nested stack with no seeded root).
  - **P0-2** the Emilien chat opens straight into a misleading **"Can't reach host"** error, because Emilien is a terminal/orchestrator agent with no mastra chat thread → host `chat.listMessages` returns 500.

- Root cause of the whole back-button family: **no `unstable_settings.initialRouteName`** on any nested `Stack`, combined with `headerShown:false` on the authenticated stack and custom back buttons that live on the *index* screens only.

## Navigation architecture (the spine of most bugs)

```
app/_layout (RootLayout: Stack, no header)
└─ (authenticated)/_layout ......... Stack  headerShown:false        ← no native back here
   ├─ (tabs)/_layout ............... NativeTabs  [Emilien | Fleet | Search | More]
   │   ├─ (home)/_layout .......... Stack (header, shadow off)
   │   │   ├─ index (Cockpit)  headerShown:false
   │   │   └─ workspaces  title:"Workspaces"        ← pushed on index → native back ✓
   │   ├─ (sessions)/_layout ...... Stack (header)
   │   │   ├─ index (Sessions)
   │   │   └─ [id] (SessionDetail)  title:"Session"  ← native back only if index seeded
   │   ├─ (search)/_layout ........ Stack (Search)
   │   └─ (more)/_layout .......... Stack
   │       ├─ index (More)  headerShown:false
   │       └─ settings/index  title:"Settings"      ← pushed on index → native back ✓
   └─ workspace/[id]/_layout ...... NativeTabs  [Chat | Changes]     ← pushed OUTSIDE main tabs
       ├─ chat/_layout ............ Stack (header)
       │   ├─ index (ChatSessions)  renders <WorkspaceBackButton/>   ✓
       │   └─ [sessionId] (ChatThread)  title from session  ← NO WorkspaceBackButton ✗
       └─ changes/_layout ......... Stack (header)
           └─ index (Changes)  renders <WorkspaceBackButton/>        ✓
```

**Key facts (verified):**
- `app/(authenticated)/_layout.tsx:10` — the stack that hosts `workspace/[id]` has `headerShown:false`, so there is **no native back chevron** to exit the workspace modal. Exit relies entirely on `WorkspaceBackButton`.
- `WorkspaceBackButton` (`screens/(authenticated)/workspace/[id]/components/WorkspaceBackButton/WorkspaceBackButton.tsx:6-18`) is a `Stack.Toolbar` left button → `router.back()` (fallback `router.replace("/(authenticated)/(tabs)/(home)")`). It is rendered by **ChatSessionsScreen** (`chat/ChatSessionsScreen.tsx:27`) and **ChangesScreen** (`changes/ChangesScreen.tsx:8`) — but **not** by **ChatThreadScreen**.
- **No layout in the app sets `unstable_settings` / `initialRouteName` / anchor** (grep across `app/**` + `screens/**` = 0 hits). Consequence: deep-linking straight to a nested stack's non-index screen produces a **single-screen stack with no back button**.

This makes the back affordance **path-dependent**:

| Reach ChatThread via | Stack contents | Native back | WorkspaceBackButton | Result |
|---|---|---|---|---|
| Workspaces → chat list → tap session (`ChatSessionsScreen.tsx:47`) | `[index, [sessionId]]` | ✓ back to list | (on list) | **OK** |
| **Cockpit → tap Emilien card** (`CockpitScreen.tsx:224-230`) | `[[sessionId]]` only | ✗ | ✗ | **P0 — stuck** |

Same mechanism for **SessionDetail**: OK via the Fleet list (`SessionsScreen.tsx:91` pushes on top of index), broken via the cockpit Fleet tap (`CockpitScreen.tsx:300`) and after new-session create (`useNewSession.ts:67`).

## Known-issue verification (the 4 flagged by the brief)

### (a) Missing back buttons on pushed screens — **CONFIRMED (P0/P1)**
Root cause above. Precise verdicts:
- `workspace/[id]/chat/[sessionId]` (ChatThread) via cockpit → **no back** (P0-1). Non-obvious escape: tap the **Changes** bottom tab → its `WorkspaceBackButton`. The main app tabs are hidden inside `workspace/[id]`, so the user is otherwise trapped.
- `(tabs)/(sessions)/[id]` (SessionDetail) via cockpit Fleet / after create → **no back to the sessions list** (P1). Less severe: the 4 main tabs remain visible, so the user can leave via another tab.
- `workspace/[id]` NativeTabs — no native way back to the cockpit; only `WorkspaceBackButton` on the two index screens.
- **Settings** — actually **OK**: `(more)/_layout.tsx:8` gives `settings/index` a header; it is pushed on the More index → native back present. (Listed as suspect in the brief, but code-trace shows a working back button, assuming the nav href resolves — see BUG-8.)

### (b) Emilien chat "chat.listMessages failed (500)" — **CONFIRMED (P0-2)**
- Tapping the Emilien card (`CockpitScreen.tsx:224-230`) opens the chat thread for the *most-recently-active chat session of the "Zuno-Emilien" project's main workspace* (`useEmilienSession.ts:14,60-104`).
- ChatThread polls `useSessionActivity` → `listSessionMessages` → `hostTrpcCall("chat.listMessages")` (`lib/relay/relay.ts:207-218`).
- On a non-2xx the helper throws `` `host ${procedure} failed (${response.status})` `` (`relay.ts:109-111`). The relay comment itself notes the host "lazily (re)creates the runtime … so this can throw when the host has no model credentials or the session has never started" (`relay.ts:198-206`).
- Emilien runs as a **terminal orchestrator** (no mastra chat thread) → host returns **500** → `useSessionActivity` sets `phase:"error"` (`useSessionActivity.ts:72-76`) → `ActivityFeed` renders **"Can't reach host / Couldn't reach the host. Retrying…"** (`ActivityFeed.tsx:120-134`).
- **Why it's a bug, not just a known limitation:** the copy is misleading (the host *is* reachable — the agent has no chat thread) and "Retrying…" implies a transient failure that never recovers. The hero card leads to a dead-end error you can't back out of (compounded by P0-1).

### (c) Token badges show "—" — **CONFIRMED as correct/intentional (P2, DEFERRED-empirical)**
- `TokenBadge` renders `` `${formatTokenCount(total)} tok` `` or `"— tok"` when `tokens` is `null` (`components/TokenBadge/TokenBadge.tsx:23`).
- `useAgentTokens` returns `null` (→ "—") whenever `!enabled || !routingKey || !sessionId || !workspaceId`, or when the host returns `null`, or on a transient error it *keeps the last value* rather than flashing "—" (`hooks/useAgentTokens/useAgentTokens.ts:65-88`).
- Source: `getSessionTokenUsage` → host `chat.getTokenUsage`, typed `SessionTokenUsage | null` — "`null` when the host has no live runtime … the UI renders "—" rather than a fabricated count" (`relay.ts:220-250`).
- **Verdict:** the mobile plumbing is complete and *correct*. Badges are "—" until a host with the `chat.getTokenUsage` procedure + a **live runtime** for the session answers. Fleet rows and per-sub-agent rows are **intentionally** always "—" (no live runtime to sum). This is **DEFERRED-empirical** (needs host rebuild + a live session to see real numbers), not a mobile defect.

### (d) STT native module absent in the sim build — **CONFIRMED as handled (PASS)**
- `useSpeechRecognition.ts:1-4` imports only **types** (`import type` — erased at runtime, so it never triggers a native require). The runtime module is loaded via a guarded `require` (`:16-23`) → on absence `SpeechRecognition = null` → `nativeModule = null`.
- Status initializes to `"unavailable"` (`:64-65`); `start()` returns `false` without throwing (`:105-109`); the composer shows an inert mic + hint. Same guarded pattern for TTS (`useTextToSpeech.ts`).
- **Verdict:** graceful degradation works exactly as intended — **not a bug**. Only nit: the hint copy is French in an otherwise-English UI (BUG-14).

## Prioritized bug list

### P0 — hero flow broken

**P0-1 · No back button on the Emilien chat when opened from the cockpit**
- **Repro:** Home (Emilien tab) → tap the Emilien card → chat thread opens → there is no back chevron / close. The `workspace/[id]` NativeTabs hide the main app tabs, so the only escape is the non-obvious "Changes" bottom tab → its back button.
- **Root cause:** `CockpitScreen.tsx:224-230` deep-links straight to `workspace/{id}/chat/{sessionId}`. `chat/_layout.tsx` has **no `unstable_settings.initialRouteName`**, so the chat `Stack` renders only `[sessionId]` (no `index` beneath → no native back). `ChatThreadScreen.tsx:186-220` sets a title + TTS `headerRight` but renders **no** `WorkspaceBackButton` (unlike `ChatSessionsScreen.tsx:27` / `ChangesScreen.tsx:8`).
- **Fix (either):** (a) render `<WorkspaceBackButton/>` in `ChatThreadScreen` (1 line, immediate); **and/or** (b) add `export const unstable_settings = { initialRouteName: "index" }` to `chat/_layout.tsx` so the deep-link seeds the sessions list beneath the thread (gives a native back). Do both for the cleanest result.

**P0-2 · Emilien chat opens to a misleading "Can't reach host" error**
- **Repro:** same tap → transcript area shows **"Can't reach host — Couldn't reach the host. Retrying…"** and never recovers.
- **Root cause:** Emilien is a terminal orchestrator with no mastra chat thread; host `chat.listMessages` → **500**; `relay.ts:109-111` throws a generic message; `useSessionActivity.ts:72-76` → `phase:"error"`; `ActivityFeed.tsx:120-134` renders the network-style error.
- **Fix:** gate the Emilien card's destination on agent type — if the session's agent has no chat thread, either (a) route to the **live terminal** (SessionDetail Terminal tab) instead of the chat thread, or (b) show a purpose-built state ("Emilien runs as a terminal orchestrator — open the terminal"). Separately, distinguish a **500 from `listMessages`** (agent/host-side) from a genuine relay-unreachable error so the copy + retry behavior are honest (`ActivityFeed`/`useSessionActivity`).

### P1

**P1-1 · No back to the sessions list on a cockpit-opened / freshly-created session detail** — `(sessions)/_layout.tsx` lacks `unstable_settings.initialRouteName`; `SessionDetailScreen.tsx:120-122` has no custom back. Deep-links from `CockpitScreen.tsx:300` and `useNewSession.ts:67` land on a single-screen stack. **Fix:** add `unstable_settings = { initialRouteName: "index" }` to `(sessions)/_layout.tsx` (native back appears; main tabs already prevent a hard trap).

### P2 (grouped)

- **P2-1 · Agent-type picker is a no-op** — `useNewSession.ts:38-41,62-65` never sends `agentType`; `chat.createSession` doesn't accept it (`packages/trpc/src/router/chat/chat.ts:26-30`). Selecting Codex/Gemini silently launches the default. **Fix:** hide/disable non-default options (or a "coming soon" note) until the backend accepts `agentType`.
- **P2-2 · Nav hrefs omit the `(tabs)` group in `MoreMenuScreen`** — `MoreMenuScreen.tsx:44,111` use `/(authenticated)/(home)` and `/(authenticated)/(more)/settings` while every sibling uses the full `(tabs)/…` path. Likely still resolves via Expo Router group-stripping, but it's inconsistent + fragile (breaks if a duplicate leaf name is added). **Fix:** align to the full paths. *(Needs 1 runtime tap to confirm resolution — downgraded from the sub-agent's "CRITICAL" after confirming group-stripping semantics + `experiments.typedRoutes` is off in `app.config.ts`.)*
- **P2-3 · Search ignores `projectsReady`** — `SearchScreen.tsx:20,66`: project-name matches silently miss while the projects collection hydrates, and "No workspaces match" can show prematurely. **Fix:** capture `isReady` for projects and gate the empty-state on both.
- **P2-4 · Terminal↔Activity toggle drops scrollback/messages** — `useTerminalStream.ts:59-137` / `useSessionActivity.ts:48-57` reset on re-enable. **Fix:** keep buffers in a ref across tab toggles; only clear on unmount.
- **P2-5 · Silent failures** — org switch (`useOrganizations.ts:27-32`, `MoreMenuScreen.tsx:45-49`), sign-out (`useSignOut.ts:18`), notification toggle (`SettingsScreen.tsx:103-110`) log to console but give the user no feedback. **Fix:** surface an `Alert`/toast on error.
- **P2-6 · Blank/edge states** — cold-launch blank while `isPending` (`RootLayout.tsx:21`); `CollectionsProvider` returns `null` with no active org (`CollectionsProvider.tsx:18-20`); social buttons not disabled while pending (`SignInScreen.tsx:49-58`); empty-projects message misleads (`WorkspacesScreen.tsx:83,90`); Changes is a placeholder (`ChangesScreen.tsx`). **Fix:** add loading/empty/error affordances.
- **P2-7 · Sign-out doesn't clear the collections cache** — `queryClient.clear()` runs but the module-level org collections cache persists (`lib/collections/collections.ts`). Low risk single-user; a data-leak seam if another user signs into the same org id on the device.
- **P2-8 · Mixed French/English copy** — dictation/permission hints are French (`ChatComposer.tsx`, `app.config.ts:52-55`) in an otherwise-English UI (intentional for the French orchestrator, but inconsistent). **Fix:** i18n or pick one language per build.
