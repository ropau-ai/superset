# Mobile UX/UI Audit — Emilien Cockpit (`apps/mobile`)

> **Date:** 2026-07-09 · **Branch:** `audit/ux-ui` (off `integration/cockpit`) · **Scope:** full-app UX/UI review, audit-only (no app code changed).
> **Auditor:** Orchestria run, governed by Emilien. **Reference specs:** `emilien-brain/notes/COCKPIT_SPEC_2026-07-08.md`; parity vs `apps/desktop` + `apps/web`.
> **A separate atelier owns navigation/back-buttons** — nav issues are noted for completeness but are not the focus here.

## Method & evidence

Findings are grounded in **code review of every screen** (≈30 source files across `app/`, `screens/`, `components/`, `hooks/`, `lib/`) plus git history and the two reference apps.

**No fresh simulator screenshots were captured — a deliberate call.** Rendering anything past sign-in requires a native dev-client build + Metro + the terminal relay + auth + a live host emitting Electric data. Booting an independent sim/Metro (Paul's iPhone 17 Pro sim `1266AB0E…` and Metro `:8090` are off-limits per brief) would either collide with that setup or, in isolation, show only the sign-in and empty states — low-value screenshots at high cost/risk. Per the brief's explicit allowance, I reasoned from code. Where a finding would benefit from on-device confirmation it is tagged **(verify on device)**.

**Overall verdict: PARTIAL — genuinely strong foundation, a few unfinished edges.** The cockpit refactor largely landed: the Emilien hero, fleet, live session detail, real chat (previously a "coming soon" stub), token UI, and full Settings are all real and, in places, more polished than the desktop/web equivalents (which are still read-only previews). The remaining gaps are one dead tab, two controls that silently do nothing, some cross-cutting polish (loading vs. empty, FR/EN mixing, tap targets, color tokenization), and a couple of perf/scroll issues.

**Severity counts: P0 = 2 · P1 = 7 · P2 = 43.** (Rubric: **P0** broken/blocking a shipped surface · **P1** clearly wrong, users will notice · **P2** polish/consistency/accessibility.)

## P0 — Broken / blocking

### P0-1 · Workspace **Changes** tab is an empty stub
`screens/(authenticated)/workspace/[id]/changes/ChangesScreen.tsx:5-16` renders only the sentence *"File changes for this workspace will appear here."* It is a first-class native tab (`app/(authenticated)/workspace/[id]/_layout.tsx:21-24`) with **zero functionality** — no diff, no file list, no loading/empty/error states. Desktop and web both ship full diff viewers (`apps/desktop` DiffPane; `apps/web` `SessionDiff`). This is the most visible "unfinished screen."
**Fix:** Either (a) build a read-only diff list from the host relay (file rows → tap → per-file diff via the existing `components/ai-elements/file-diff-tool.tsx`), or (b) if out of scope tonight, remove the tab from `_layout.tsx` so the app doesn't advertise an empty feature. Don't ship an advertised-but-empty tab.

### P0-2 · Notifications **"Granularity"** control is a silent no-op
`SettingsScreen.tsx:195-200` renders a segmented "Emilien only / Whole fleet" control, but `lib/notifications/preferences.ts:75` states verbatim: `TODO(watcher): AgentNotificationWatcher does not yet read this scope`. So the watcher (`lib/notifications/AgentNotificationWatcher.tsx`) ignores the setting — toggling it changes nothing. A shipped Settings control that appears functional but does nothing erodes trust in the whole panel.
**Fix:** Wire `AgentNotificationWatcher` to read `useNotificationScope()` and suppress fleet notifications when scope = `emilien`. If it can't ship tonight, hide the control (only show it once the watcher honors it), don't leave a dead switch.

## P1 — Clearly wrong

### P1-1 · No global ErrorBoundary → one render throw white-screens the app
`screens/RootLayout/RootLayout.tsx:18-45` wraps the tree in providers but there is **no error boundary anywhere** (grep-confirmed). Any render-time throw in a screen (e.g. a malformed relay payload reaching `ActivityMessage`) crashes the entire app to a blank/red screen with no recovery.
**Fix:** Add an `ErrorBoundary` around `<Stack>` in `RootLayout` with a branded "Something went wrong — reload" fallback; optionally per-tab boundaries so one screen's failure doesn't kill the cockpit.

### P1-2 · Systemic FR/EN language mixing (no i18n)
The app mixes French and English, sometimes **in the same sentence/screen**:
- `EmilienCard.tsx:71` — *"Emilien veille — no live conversation yet."* (FR+EN in one string).
- `FleetSection.tsx:176-181` — empty state fully French; most of the app is English.
- `ChatComposer.tsx:104-107` — voice hints French (*"Autorise le micro dans les Réglages…"*) while `ChatThreadScreen.tsx:173-177` disabled-hints are English.
- `app.config.ts:47-54` — mic/speech **system permission prompts** are French.
There is an `expo-localization` plugin but no actual i18n; strings are hardcoded and inconsistent.
**Fix:** Pick one UI language (English reads as the default elsewhere) and make copy consistent, or introduce a minimal string table. At minimum, de-mix the composer and the Emilien card.

### P1-3 · Cockpit conflates **loading** with **empty**
On cold start with no Electric cache, `FleetSection.tsx:172-182` shows the *"Emilien veille. Aucun sous-agent actif."* empty state even when agents actually exist — because `groups.length === 0` is true while data is still hydrating. `CockpitScreen.tsx` has no skeleton. Users can briefly be told the fleet is idle when it isn't.
**Fix:** Thread `isReady` from the `chatSessions` live query into the cockpit; render a 2–3 row fleet skeleton (the `SubAgentsPanel` skeleton pattern already exists) when `!isReady && groups.length === 0`, and only show the "veille" empty state once ready.

### P1-4 · Session-detail loading state is a blank screen
`SessionDetailScreen.tsx:174-180`: while `!session && !sessionsReady` it returns `null` — opening a session before hydration shows an empty dark screen (no spinner/skeleton), then either content or "Session not found."
**Fix:** Render a header + terminal skeleton while `!sessionsReady`; reserve "Session not found" for `sessionsReady && !session`.

### P1-5 · Live terminal is a nested same-axis ScrollView (fiddly + cramped)
The whole screen is a vertical `ScrollView` (`SessionDetailScreen.tsx:113`) and the terminal body is **another vertical `ScrollView`** (`LiveTerminal.tsx:90`) inside a fixed `h-96` (384px) box (`LiveTerminal.tsx:213`). Same-axis nested scrolling fights gestures on iOS — scrolling terminal history often scrolls the page instead — and 384px is a small "hero" for the app's headline panel. **(verify on device)**
**Fix:** Make the session screen a non-scrolling flex column and let the terminal own vertical space (`flex-1`), or lift the outer container to a `FlatList` with the terminal as a full-height item. Consider a full-screen terminal affordance.

### P1-6 · Chat transcript is an unvirtualized ScrollView
`ChatThreadScreen.tsx:221-236` renders **all** messages in a plain `ScrollView` and calls `scrollToEnd` on every new message (`:91-98`). For Emilien's 24/7 long-running conversation this grows unbounded — memory + jank + expensive layout. Desktop/web use virtualized conversation lists.
**Fix:** Move to a `FlatList` (ideally inverted) or `LegendList` (already used in `WorkspacesScreen`) with windowing; keep auto-scroll only when the user is near the bottom.

### P1-7 · Destructive **Log out** has no confirmation (×2 places)
`MoreMenuScreen.tsx:127-133` and `SettingsScreen.tsx:148-153` both sign out on a single tap with no `Alert.alert` confirm. Easy to mis-tap; logging back in requires the full OAuth round-trip.
**Fix:** Wrap `signOut` in a confirm dialog ("Log out of Emilien?"). Consolidate to one log-out entry point (see P2 redundancy note).

## P2 — Polish / consistency / accessibility

### Cross-cutting (global)
- **P2-G1 · Status bar style not set explicitly.** No `expo-status-bar`/`<StatusBar>` anywhere; relies on `userInterfaceStyle:"dark"` (`app.config.ts:18`) for light status-bar content. Add `<StatusBar style="light" />` to be deterministic across screens/sheets. **(verify on device)**
- **P2-G2 · 1-second full-tree re-render.** `useNow(1000)` in `CockpitScreen.tsx:34-41` and `SessionDetailScreen.tsx:25-32` re-renders the whole tree (incl. FleetSection / terminal) every second just to tick durations. 15–30s is plenty for "up 2h 14m" / "last active"; battery-relevant on a cockpit that's left open.
- **P2-G3 · `card` == `background` in dark theme.** `theme.ts:47-48` / `global.css:45-46` set both to `hsl(0 0% 3.9%)`, so every `bg-card` surface (fleet groups, sub-agent rows, settings, chat input) is separated from the page only by a 1px border → flat hierarchy. The Emilien hero "pops" only because of its bespoke ember wash. Consider a slightly lighter card (e.g. `hsl(0 0% 7%)`) so elevation reads without per-component hacks.
- **P2-G4 · Status colors not tokenized.** Greens appear in ≥3 shades — `#34d399` (`LivePulseDot`/`EmilienCard.tsx:65`), Tailwind `emerald-500` (host icons), `#3fb950` (`WorkspaceRow.tsx:43`); reds as `#f85149`/`rose-*`; no `success`/`warning` tokens exist in `theme.ts`. Define semantic tokens (success/warning/info/live) and reference them everywhere.
- **P2-G5 · Status color semantics are counterintuitive.** `AgentStatusBadge.tsx:22-53` maps **working → amber** (reads as "warning/caution") and **idle → emerald/green** (reads as "active/good"). Consider green=working/live, muted=idle, amber reserved for waiting/attention.
- **P2-G6 · Sub-11px type + no Dynamic Type.** `text-[10px]` (AgentTypeChip, "Orchestrator" badge) and `text-[11px]` (TokenBadge, branch labels) fall below iOS legibility guidance, and `allowFontScaling` is never handled, so accessibility text sizes don't scale. Bump the smallest labels to 11–12px and audit for Dynamic Type.
- **P2-G7 · Reduce-Motion ignored.** Infinite Reanimated pulses (`LivePulseDot`, `AgentStatusBadge` `PulsingDot`, `ChatComposer` mic radar) run regardless of iOS "Reduce Motion." Gate the repeats behind `AccessibilityInfo.isReduceMotionEnabled()`.
- **P2-G8 · No pull-to-refresh / manual recovery** on any list. Electric is live so it's usually fine, but there's no user affordance to force a refresh when something looks stale.
- **P2-G9 · Typographic scale defined but unused.** `components/ui/text.tsx` exposes `h1–h4`/`lead`/`muted` variants, yet screens hardcode `text-xl`/`text-2xl`/`text-sm` etc. Adopt the variants for consistent hierarchy.
- **P2-G10 · Inconsistent loading idioms.** `SubAgentsPanel` uses skeletons; most screens render `null` while not ready (`RootLayout.tsx:21` returns `null` on `isPending` → blank after splash). Standardize a skeleton/spinner idiom.

### Sign-in (`SignInScreen.tsx`)
- **P2-S1 · Off-brand front door.** Title "Welcome to Superset" / "Sign in to get started", zero ember, no Emilien identity (`:40-45`). The app icon is now the Emilien orbital mark (commit `5dea28dc5`), but the first screen doesn't carry the cockpit brand the spec calls for.
- **P2-S2 · No loading state on OAuth buttons.** `SignInScreen.tsx:17-30` awaits `signIn.social` with no spinner/disable → double-tap risk, no feedback.
- **P2-S3 · Social icon contrast bug.** `SocialButton.tsx:58-59` derives `iconColor` from `useColorScheme()` (the **system** scheme) while the app is force-dark; on a light-mode device the GitHub glyph renders black on the dark button. Key it off the app theme, not the system scheme.

### Home cockpit (`CockpitScreen` / `EmilienCard` / `FleetSection`)
- **P2-H1 · TokenBadge isn't tappable.** Spec wants tap → in/out breakdown; `useAgentTokens` already fetches `input`/`output`, but `TokenBadge.tsx` never surfaces them and has no press target.
- **P2-H2 · "Fleet" vs "Sessions" naming drift.** Tab label "Fleet" (`(tabs)/_layout.tsx:25`) + home section "Fleet" vs. list screen title "Sessions" and empty copy "No sessions yet." Pick one noun.
- **P2-H3 · Fleet rows are a column of "— tok".** `FleetSection.tsx:67` shows honest em-dashes per row (no live runtime to sum). Correct per spec, but visually reads as unfinished — consider omitting the per-row token chip until a value exists, keeping it only where real.
- **P2-H4 · Hardcoded greens** in `EmilienCard.tsx:65` and `FleetSection.tsx:55` (see G4).

### Fleet / Sessions list (`SessionsScreen.tsx`)
- **P2-F1 · Prominent "compose" button vs. narrative.** The `square.and.pencil` toolbar button (`:127-131`) foregrounds session creation, but the cockpit story is "Paul watches, Emilien acts"; the spec wants agent creation discreet. Consider demoting it.
- **P2-F2 · No loading skeleton** (blank while `!sessionsReady`).

### Session detail (`SessionDetailScreen` / `LiveTerminal` / tabs / header)
- **P2-D1 · Tab triggers below 44pt.** `ui/tabs.tsx:47-48` uses `px-2 py-1` in an `h-9` list — Terminal/Activity targets are ~30px tall.
- **P2-D2 · Terminal has no copy-all / share.** Text is `selectable` only; add a copy button to the terminal header (`LiveTerminal.tsx:217-230`).
- **P2-D3 · Brief wording divergence.** Brief lists "Terminal / Activity / SubAgents **tabs**"; implementation is 2 tabs + an always-visible SubAgents panel above (`SessionDetailScreen.tsx:136-172`). The panel approach is arguably better — noting only so the divergence is intentional/documented.

### Chat (`ChatThreadScreen` / `ChatComposer`)
- **P2-C1 · Composer buttons below 44pt.** Mic and send are `size-10` (40px) with no `hitSlop` (`ChatComposer.tsx:120,168`).
- **P2-C2 · Wrong-register empty copy.** Chat reuses `ActivityFeed`'s "the agent's commands and file edits will appear as it works" (`ActivityFeed.tsx:149`) — for a conversation it should say something like "Say hello to Emilien."
- **P2-C3 · Hardcoded keyboard offset.** `keyboardVerticalOffset={insets.top + 44}` (`ChatThreadScreen.tsx:183`) assumes a 44pt header; may misalign the composer above the keyboard on some devices. **(verify on device)**
- **P2-C4 · No token-streaming and no "stop generation."** Replies arrive per-poll (chunked, not streamed) and there's no abort. Acceptable for an observation cockpit; noted as a desktop divergence.

### Workspace detail
- **P2-W1 · Nested NativeTabs swap the whole tab bar.** Entering `workspace/[id]` replaces the main Emilien/Fleet/Search/More bar with a Chat/Changes bar (`workspace/[id]/_layout.tsx`), exited via a bespoke `WorkspaceBackButton`. Jarring context switch; verify the mental model holds (nav atelier territory).
- **P2-W2 · Inconsistent timestamp format.** `ChatSessionsScreen.tsx:54` uses raw `toLocaleString()` while the rest of the app uses `formatDistanceToNow` ("2h ago").
- **P2-W3 · Extra hop to the conversation.** Tapping a workspace redirects to a session **list** (`workspace/[id]/index.tsx` → `/chat` → list), not the latest chat — one more tap than needed for the common case.

### Search (`SearchScreen.tsx`)
- **P2-SR1 · Searches only workspaces** (name/branch/project, `:25-42`) — not sessions, fleet agents, or messages, which is where Paul lives. Desktop has a command palette + file search. Consider adding session/agent search.
- **P2-SR2 · Silent 50-result cap** (`:41` `slice(0,50)`) with no "showing 50 of N."

### More menu (`MoreMenuScreen.tsx`)
- **P2-M1 · Triple-redundant org switching / double log-out.** Org switch exists in More, Settings, **and** the cockpit header; log-out in both More and Settings — with divergent behavior (More does `router.replace` to home on switch; Settings' switch doesn't navigate). Pick one home for each.
- **P2-M2 · "More" is nearly empty** (Org block + a single "Settings" row + Log out) and largely duplicates Settings; consider folding it in or enriching it.
- **P2-M3 · No screen title.** `headerShown:false` + no in-body heading, while sibling tabs have titles — header-pattern inconsistency (cockpit custom header vs. native titled headers vs. none).

### Settings (`SettingsScreen.tsx`)
- **P2-ST1 · Appearance rows are dead.** Theme ("Dark") and Accent ("Ember") rows (`:160-177`) are display-only with no action — two inert rows. The footer discloses "light coming," which softens it, but they still read as unfinished.

### New Session sheet (`NewSessionSheet.tsx`)
- **P2-N1 · Agent-type picker is cosmetic.** `:59-60` comment: the Codex/Gemini/… selection is *"not yet sent to the backend."* Choosing Codex then a workspace still launches the default agent — a misleading affordance (mitigated only by being discreet, per spec). Either wire it or visually mark it "coming."
- **P2-N2 · Chip/row tap targets** ~32–40px (`:78,101`) below 44pt.

## Parity — where mobile diverges

### vs. `apps/desktop` and `apps/web`
Both reference apps treat agent sessions as **read-only previews** today — web literally shows "Follow-ups on web are coming soon," and neither exposes token usage. **Mobile is actually ahead** on: a real send-capable chat, live token counters (`useAgentTokens`), the pinned-orchestrator hero, a live sub-agent panel, and voice (TTS/dictation). So "parity" is less about catching up and more about the few places mobile under-delivers:

| Surface | Desktop / Web | Mobile | Gap |
|---|---|---|---|
| **Diff / Changes** | Full diff viewer (file tree, +/- lines, threads) | **Empty stub** | **P0-1** — the single biggest gap |
| **Chat history perf** | Virtualized conversation | Unvirtualized ScrollView | P1-6 |
| **Search** | Command palette + file/workspace search | Workspaces only | P2-SR1 |
| **Rich composer** | Slash commands, mentions, attachments, model/thinking pickers | Plain text + mic | Acceptable for mobile; note |
| **Error handling** | Error states / boundaries | No global boundary | P1-1 |
| **Tool-call approval** | Approve/reject controls | Observe-only | By design (Paul observes) |

**Top gap vs. desktop:** the workspace **Changes/diff viewer is a bare stub** — desktop's richest surface is entirely absent on mobile.

### vs. the Cockpit Spec (`COCKPIT_SPEC_2026-07-08.md`)
Spec adherence is high. Delivered: ember accent + orbital logo + generated icons (`5dea28dc5`); Emilien-centric Home with pinned hero + fleet + elegant empty state; real Emilien chat (was a stub) with mic placeholder now functional; token UI with strict "no fake numbers" (`useAgentTokens` → "—"); full Settings (was 3 empty stubs); Emilien/Fleet/Search/More tabs; discreet agent-type picker. **Spec deviations:** token badge lacks the "tap → in/out breakdown" the spec asks for (P2-H1); the agent picker isn't wired (P2-N1); the notification granularity is disclosed in spec as future but shipped as a live-looking no-op (P0-2).

## What's genuinely good (keep)

- `useAgentTokens` — honest polling, `AppState`-gated, last-value-on-error, never fabricates a number. Model implementation of the spec's "zero fake data" mandate.
- State coverage in `LiveTerminal`, `ActivityFeed`, `SubAgentsPanel` — relay-not-configured / host-offline / connecting / error / empty / success are all handled with clear copy and retry.
- `ActivityMessage` — markdown, collapsible reasoning, rich tool cards, attachments, unknown-part fallback, read-aloud. Mirrors desktop faithfully.
- The Emilien hero + orbital logo + restrained single-ember accent — the brand reads, and chromatic restraint is respected.
- Native primitives used well: NativeTabs, `Stack.SearchBar`, `@expo/ui` BottomSheet, LegendList in `WorkspacesScreen`.
